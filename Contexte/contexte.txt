La différence fondamentale
MCD (Modèle Conceptuel de Données)

C'est la méthode Merise (française)
On parle d'entités et d'associations
C'est indépendant de toute technologie — c'est juste la logique métier
Outil : Looping, PowerAMC

Diagramme de classes UML

C'est la méthode UML (internationale)
On parle de classes, attributs, méthodes et relations
Il représente à la fois la structure des données ET le comportement (les méthodes)
Outil : StarUML, PowerDesigner


Pour votre projet, c'est lequel ?
Votre école (IAI-Togo) utilise UML → donc c'est le diagramme de classes qui est attendu dans votre mémoire, pas le MCD Merise.
Le MCD qu'on a fait ensemble ressemble plus à un diagramme entité-relation qui sert à concevoir la base de données. C'est complémentaire.

Comment fonctionne le diagramme de classes
Pensez à votre fichier Excel de Moov. Il y a des entités réelles :
Une ENTREPRISE (Company)
    → a plusieurs LIGNES (Line)
    → reçoit des FACTURES (Invoice)
    → emploie des UTILISATEURS (User)
Chaque classe représente un concept réel du projet :
┌─────────────────────────┐
│        Company          │  ← Nom de la classe
├─────────────────────────┤
│ - id : Guid             │  ← Attributs (les données stockées)
│ - numero_contrat : String│    (le "-" = privé, personne dehors y accède directement)
│ - raison_sociale : String│
│ - statut : String       │
├─────────────────────────┤
│ + getLignes() : List    │  ← Méthodes (ce que la classe peut faire)
│ + getFactures() : List  │    (le "+" = public, accessible de l'extérieur)
└─────────────────────────┘

Les relations — c'est là que ça devient important
1. Association simple → "est lié à"
Company ————————— Invoice
Une entreprise est liée à des factures.
2. Avec cardinalités → "combien ?"
Company "1" ————— "0..*" Invoice
Une entreprise peut avoir zéro ou plusieurs factures.
Une facture appartient à une et une seule entreprise.
3. Composition → "est constitué de, vie liée"
Company "1" ◆——— "1..*" Line
Le losange plein ◆ = si l'entreprise est supprimée, ses lignes sont supprimées aussi. La ligne ne peut pas exister sans l'entreprise.
4. Agrégation → "possède, mais vie indépendante"
Company "1" ◇——— "0..*" Invoice
Le losange vide ◇ = si l'entreprise est supprimée, les factures peuvent être conservées (pour archivage). La facture peut exister sans l'entreprise.
5. Héritage → "est un"
Utilisateur
    △
    │
  ┌─┴──┐
Payeur  Employé
Le triangle vide = Payeur est un Utilisateur, Employé est un Utilisateur. Ils héritent de tous les attributs et méthodes de Utilisateur.
